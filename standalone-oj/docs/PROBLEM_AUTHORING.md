# 出题与测试规范

题包是管理员向服务器导入的 JSON，包含题目定义、初始代码、函数驱动、五语言参考实现和完整测试集。它不是前端展示格式，不能放到 public 目录。固定规范使 AI 能稳定生成题目，也使审核者能复现每个期望输出。

## 题意先于代码

先明确任务、输入输出、约束、唯一答案或可接受答案规则、数据类型、算法和复杂度。不要只把一个已有算法模板换个标题。原创题写清情境但不要增加与算法无关的限制；来源标记为“软件协会原创”。引用训练题型时保留真实 HTTPS 来源，题面与测试自行整理，不能声称复制的内容是原创，也不能复制官方隐藏测试。

正式题面必须让入门读者知道每个变量是什么意思、下标从 0 还是 1 开始、空输入是否允许、输出顺序、多个合法解如何处理、是否有多组输入，以及整数是否可能溢出。

## JSON 字段

| 字段 | 类型与要求 |
| --- | --- |
| `slug` | 1–100 位小写字母、数字、连字符，首位为字母或数字；稳定且唯一 |
| `title` | 非空，最多 200 字符 |
| `difficulty` | `EASY`、`MEDIUM`、`HARD` |
| `tags` | 最多 20 个字符串，每个最多 50 字符，与实际方法一致 |
| `description` | Markdown 题面，解释全部任务条件 |
| `inputFormat` / `outputFormat` / `constraints` | 独立字符串，明确协议和范围 |
| `sourcePlatform` | 原创用 `原创`，引用题型保留实际来源 |
| `sourceUrl` / `sourceId` / `sourceNote` | 原创 URL / ID 留空，note 为 `软件协会原创`；引用题型保留 HTTPS 链接和来源说明 |
| `modes` | `['STDIO']`、`['FUNCTION']` 或两者，不能重复 |
| `defaultMode` | 必须属于 modes |
| `checker` | `TOKENS` / `UNORDERED_TOKENS` / `UNORDERED_LINES` / `ANY_OF` / `SPECIAL_JUDGE` |
| `checkerSource` | 自定义校验器的 Python 源码，仅 SPECIAL_JUDGE 必填，UTF-8 最多 64 KiB |
| `profiles` | c / cpp / java / python / rust 的初始代码及可选函数驱动 |
| `cases` | 1–500 个测试用例，至少一个公开样例 |
| `references` | 每个语言和每个题目模式都必须有参考实现 |

精确字段和校验见 `backend/src/main/java/io/sapoj/dto/judger/ProblemPack.java`、`OjService.validatePack` 和 `tools/ojctl.py`。最大题包 4 MB；单个输入 1 MiB、期望输出 256 KiB，测试总量最多 2 MB。CLI 以 UTF-8 字节做更保守的检查。

每个用例只包含：

```json
{"name":"boundary-01","input":"0 0\n","expectedOutput":"0\n","sample":false}
```

`sample` 必须是真正布尔值，字符串 `"false"` 不合法。公开样例用于用户运行；正式提交使用全部测试，隐藏输入和输出不向普通账号公开。用例名称唯一；相同输入不能有相互冲突的标准答案。

## 比较器

`TOKENS` 忽略空白分隔的细微差异，按顺序比较 token。换行、多个空格等通常不决定结果，但 token 内容和顺序必须一致。

`UNORDERED_TOKENS` 比较 token 的多重集合，允许 token 顺序不同；它不是“任意合法解”通用检查器，也不是浮点容差检查器。题目存在多种合法方案时，可使用 `ANY_OF` 列出有限答案，或 `SPECIAL_JUDGE` 按题意校验任意合法解；详见 [多答案题与校验器](MULTIPLE_ANSWERS.md)。

当前没有 `EXACT`、特殊评测程序或浮点容差字段。不要生成服务器不支持的 checker 名称。

## 五语言与模式

语言键固定 `c`、`cpp`、`java`、`python`、`rust`。每个启用模式必须齐全五种语言，算法、范围与输出语义一致。完整程序使用 Main.java / `public class Main`；Java 函数题通常使用 Solution 与对应驱动。不能依赖外部包、宿主文件或网络。

模板结构：

```json
{
  "profiles": {
    "cpp": {
      "starterStdio": "完整程序初始代码",
      "starterFunction": "函数或 Solution 初始代码",
      "functionDriver": "受控输入输出驱动，包含唯一 __USER_CODE__"
    }
  },
  "references": {
    "cpp": {"STDIO":"完整参考程序","FUNCTION":"函数参考实现"}
  }
}
```

上面只展示一门语言；实际题包需五门齐全。仅 STDIO 的题目可以把另外两个 profile 字段留空，references 只保留 STDIO。仅 FUNCTION 的题目不必假装支持完整程序模式。

核心函数编译时自动加入常用标准库，详见 [核心函数模式](CORE_MODE.md)。已有显式引包兼容，完整程序模式仍需自行引包。

函数驱动必须且只能含一次 `__USER_CODE__`。驱动负责读取输入、调用题目规定函数和按协议输出。函数签名、数组长度、链表 / 树的序列化、返回值 ownership 和空值约定必须在题面、模板、驱动与参考实现中一致。C 返回动态数组或链表时，明确内存所有权并由驱动正确释放；不能在返回指针后引用已经释放的内存。

参考代码至少在读入 / 参数、核心处理和输出 / 返回三个位置有针对性注释。解释为什么这样做，避免无意义的逐行翻译。代码初始模板保留必要读取与函数签名，但不把完整答案作为默认起始内容。

## 测试覆盖矩阵

生成之前写一张矩阵，例如：

| 类别 | 要验证的性质 | 用例设计 |
| --- | --- | --- |
| 最小规模 | 初始化、空结构、单元素、循环入口 | 题意允许的最小 n 和特殊结构 |
| 最大规模 | 复杂度、内存、最坏分支 | 最大 n、最大边数、重复结构 |
| 边界值 | 溢出、负号、端点、取模 | 上下界、零、相反数、接近类型范围 |
| 结构变化 | 分支正确性 | 单调、逆序、重复、全相等、稀疏、稠密 |
| 反例 | 打破常见错误算法 | 贪心错误、漏端点、错误 DP 顺序、少一次循环 |
| 随机差分 | 综合正确性 | 固定种子、小规模可穷举 oracle |
| 协议 | 五语言和两模式一致性 | 合法空白、空值、序列化、输出顺序 |

不同算法选择实际相关类别，不要求题面禁止的输入。公开样例要简单、有解释；隐藏测试要有足够区分度。不要仅生成相似随机数据，也不要用极大重复数据充数量。

建议一般题 20–100 个有意义用例，复杂题根据分支与预算决定数量。500 是接口上限，不是质量目标；五语言、两模式、三轮最多形成 15000 次用例执行，需要考虑整个判题组的 600 秒默认预算。

## 独立 oracle 与差分

复杂题至少有两份相互独立的求值方法：小规模暴力 / 穷举 oracle 与将发布的高效算法。不能把同一份逻辑复制到两处就称为独立验证。

1. 固定随机种子，生成受控小规模输入。
2. 使用简单可审计的 oracle 算出结果。
3. 在服务器沙箱中运行五语言实现，与 oracle 结果比较。
4. 发现不一致时缩小反例，修复算法或数据生成器，再生成全部期望值。
5. 保存种子、生成版本、覆盖矩阵和差分统计。

生成器与可信 oracle 可以作为 AI 编写的受控脚本运行；来自题包、学生提交或未经审阅的参考代码不能直接在宿主机执行。复杂算法也可以把 oracle 放入判题沙箱运行，收集其结果后再生成标准输出。

数学常量或简单算术无需刻意写一份复杂“慢解”，但仍要手算边界并交叉验证五语言输出。附带 `generate_example.py` 展示这种固定协议的工程流程。

## 常见错误实现检测

准备若干刻意错误的实现，作为测试集的反例检查：

- 少处理首项 / 末项、把 `<` 写成 `<=`、只检查一部分数据。
- 误用 32 位整数、忽略负数、错误取模、错误初始化。
- 贪心策略缺乏成立条件、DP 顺序错误、图搜索漏标记。
- 只匹配公开样例、输出固定答案、额外输出提示文本。
- 时间复杂度不满足最大规模，但在小样例通过的实现。

每个错误实现应至少被一个对应类别的用例拒绝。记录它的预期失败原因和实际判定；不能只记录“全部样例通过”。错误代码同样送到服务端沙箱执行。

## 最终验证与修改

调用 `tools/ojctl.py validate`，保持五语言开启，等待完整三轮 `AC`。修改题目、测试、驱动或参考代码会使旧验证失效，需要重新跑。改变语言限制或工具链也会改变验证签名。

验证通过不等于题意已经审校。发布前再核对约束、复杂度、样例解释、五语言注释、图解、数据来源、题解与当前 revision。任何算法修改都不能只靠旧的参考程序验证记录。

## 生成示例

```bash
python3 tools/generate_example.py --output examples/my-sum --slug original-my-sum --seed 20261013
python3 tools/ojctl.py lint examples/my-sum/pack.json
```

输出 pack.json、solution.json、coverage.json，包含 41 个可重现测试和五份参考代码。生成器拒绝覆盖已有文件。要研究生成过程，直接阅读脚本中的 CODES、STARTERS、样例矩阵和固定 seed；不要把例题简单改名后当成新的复杂算法题。
