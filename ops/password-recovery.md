# 忘记密码

网页 `/forgot-password` 是唯一找回页面。用户端登录、管理端登录及 Android 登录页均提供入口；App 使用系统浏览器打开，不托管邮箱或网页密码。打开页面仅获取图形验证码，不发送邮件。

## 流程和接口

1. 填写注册账号（学号）、图形验证码，主动点击发送。
2. `POST /api/auth/password-recovery/send`：`account`、`captchaId`、`captcha`。不接受自定义收件邮箱，服务端读取用户资料中的 QQ，拼接 `@qq.com`。
3. 返回随机 `requestId`、冷却时间及统一提示。不返回账号是否存在、姓名、QQ 等个人资料；无效账号也计入限额，但不发信。
4. `POST /api/auth/password-recovery/reset`：`requestId`、六位 `code`、`newPassword`。邮箱验证成功后保存 BCrypt 密码，使该账号所有找回凭据失效、注销旧登录，并清除登录失败锁定。需要重新登录，不自动创建登录会话。
5. 管理员修改过 QQ 或密码后，之前的验证码不再可用。停用/删除账号不能通过找回密码恢复访问。

QQ 填错、无法收信或密码仍不正确，页面明确提示联系管理员核验身份；此流程不能修改注册 QQ，管理员也不能在日志中查看验证码。

## 防滥发默认值

| 范围 | 限制（滚动窗口） |
| --- | --- |
| 同账号或同 QQ 邮箱 | 3 分钟一次，24 小时最多 3 次 |
| 同 IP | 1 小时最多 5 次，24 小时最多 10 次 |
| 整个找回流程 | 1 小时最多 8 次，24 小时最多 30 次 |
| 验证码 | 15 分钟过期，最多 5 次校验尝试，一次性使用；重发后旧码失效 |
| 邮件队列 | 已有 5 条未完成邮件时暂不受理新找回申请；仍遵守发送完成后间隔 65 秒，不绕过队列 |

图形验证码强制校验，与注册是否免图形验证码的设置无关。发送、校验和验证码图片接口还有现有 IP 请求限流。正式部署需维持 nginx 覆盖 `X-Real-IP`，不要将 Spring Boot 端口直接暴露公网。

`sys_password_recovery` 保存限额和挑战状态，使用邮件工作器行锁串行检查并提交，防止多请求/多实例并发越过配额。验证码保存带 `jw.aes-key` 的 HMAC 摘要；邮件正文沿用加密队列。错误校验次数独立于返回异常提交，不能通过失败回滚绕过。申请和邮件入队同事务，生成失败不遗留有效凭据。每天 04:30 清理 48 小时前记录，限额重启不清零。

日志仅记录账号、姓名、触发原因和重置结果，不记录验证码、明文密码。密码邮件失败不允许管理员重试旧验证码，应由用户重新申请。SMTP 接受不代表最终投递，请提示检查垃圾箱。

## 模板与上线

事件 `PASSWORD_CODE` 的参数保持 `name`、`account`、`code`、`expiresInMinutes`，与模板标识解耦。需全局 SMTP 启用、绑定匹配模板且模板启用。

## 本地验证（不发邮件）

- 后端 `PasswordRecoveryServiceTest`：真实 H2 事务/并发锁，限额、错误计数、过期、重放、资料变更、一次性重置、实际钩子与加密队列联通。
- `PasswordRecoveryControllerTest`：请求校验、仅 POST 发送；`AuthServiceTest`：只清除找回账号的登录锁定。
- 用户端 Vite 3001 启动后，设置 `PLAYWRIGHT_MODULE` 指向本机 Playwright，运行 `node ops/password-recovery-ui-check.cjs`。所有 API 都被本地模拟，不发送真实邮件、不修改真实密码。
- `ops/enable-password-email.cjs` 默认只检查；只有显式设置 `ENABLE_PASSWORD_EMAIL=yes` 才启用已绑定模板。登录凭据仅由环境变量传入，不能写入版本库。
