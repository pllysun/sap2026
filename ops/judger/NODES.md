# 判题执行节点（1.5.10）

平台仍使用一个业务 Docker 容器。内置 go-judge 由轻量 Python 控制服务管理，控制端口 5051 仅监听容器回环；go-judge 端口 5050 也不对外发布。停止节点会终止判题进程与其沙箱子进程、撤销任务租约，保留控制服务以便再次启动。停止后网站、数据库、Redis、OCR 正常工作；Docker 健康检查检测业务服务和节点控制服务，不要求被管理员停止的执行进程继续运行。内置节点启停意图保存在数据库，容器升级重启后恢复。

管理入口：管理端 → 算法题库 → 统一管理 → 判题节点。可添加独立节点、启停、刷新、修改连接配置与并发上限、移除已停止的独立节点。连接令牌只在输入时使用，后端加密保存，查询接口不回传；加密密钥位于持久化业务数据卷的 `judger-node.key`，备份数据库时需要同时备份该文件。

## 独立节点

需要原生 Linux x86_64 Docker 主机。节点运行 `pllysun/sap:1.5.10` 的 node-only 模式，不启动 Java 业务服务、Nginx、数据库、Redis 或 OCR，也不需要业务凭据。语言环境与平台保持一致：C、C++、Java 27、Python、Rust。地址使用公网 HTTPS 或内网 HTTP。平台必须能够访问节点；公网部署可使用脚本的 TLS 参数，也可由服务器反向代理提供 HTTPS。

从管理端部署说明下载到同一目录：`install.sh`、`prepare.py`、`seccomp.json`。先生成连接令牌，再部署：

```sh
openssl rand -hex 32 > node.token
chmod 600 node.token
sudo bash install.sh --token-file "$PWD/node.token" \
  --cpu 2 --memory-mb 1280 --concurrency 2
```

每个并发任务预留至少 640 MiB，另外为宿主系统保留至少 512 MiB。节点只获取明确的沙箱能力与专用 cgroup 子树，不使用 privileged 容器。安装脚本支持 v1/v2 的资源准备并通过 systemd 保留重启后的配额。默认资源前缀为 `sapjudgernode`，容器名为 `sap-judger-node`；同机安装多节点时分别设置 `--prefix`、`--name`、`--port`。不要复用其他运行节点的 cgroup 前缀。

可选参数：`--tls-cert`、`--tls-key`（PEM 文件），`--push-url https://平台域名/api/oj-nodes/节点ID/heartbeat`。节点 ID 可先在管理端登记地址取得。已部署节点修改环境变量需要按原参数重新创建节点容器，并保留数据卷与令牌文件；仅重启不会修改 Docker 环境变量。没有主动上报地址时平台每 5 秒获取节点自行测量的资源报告。连接断开、报告超时（15 秒）、版本不匹配或满载时停止派发。

## 调度与恢复

节点按 CPU 配额、内存预算（每任务 640 MiB）、自身并发上限报告容量。管理员的并发上限可进一步缩小容量，平台最多 32 个并行任务；主机剩余内存不足 160 MiB 时节点不再接收新任务。所有启用节点共同参与分配，优先选择 `(当前任务数 + 1) / 节点容量` 最小的节点。租约在节点内原子分配，避免多个平台请求超额执行。

一项任务的编译、所有测试用例及编译文件清理固定到同一节点。连接中断或执行服务停止时，平台最多尝试三个不同的节点，重新完整执行该任务，并保留节点异常、切换与完成事件。没有可用任务位时运行/提交接口返回业务错误 503，前端展示具体原因并保留草稿。已接受的任务进入短队列；运行记录保留提交人、提交源码、节点、尝试次数、时间线与结果。

用户只能查询本人的提交源码；管理员可从运行记录的“提交的代码”页查看原始快照。节点心跳使用独立机器令牌，不接受普通登录凭证。全部控制器接口接入项目的操作日志切面，记录操作人、接口、时间、耗时和结果，不把源码、隐藏用例或连接令牌写入操作日志。

## 验证范围

`JudgerNodesTest` 覆盖容量权重、满载/离线/超时报表/版本不匹配、节点切换、全任务租约绑定、机器认证、敏感字段隔离、JSON 数值格式及密钥持久化。`probe-node-supervisor.py` 在生产同内核的独立测试容器验证真实执行、启停、内存释放、租约与中途停止。

cgroup v1 的原生 x86_64 节点执行已实测。2026-10-02 在 pllysun.top 的 Debian 12 / Linux 6.1 原生 x86_64 主机完成 cgroup v2 验收：八任务并发、五语言双模式正式提交、资源隔离、反复启停与内存释放、任务故障切换、控制服务重启恢复均通过。该部署使用 1.5.10 镜像及本次修正的节点控制器挂载，具体路径和维护方式见 [独立节点部署记录](PLLYSUN-NODE-20261002.md)。部署脚本仍拒绝 ARM 主机；Docker Desktop 的 amd64 模拟结果不能代替原生验收。
