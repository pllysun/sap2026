## 修复范围

| 审查问题 | 本次处理 |
| --- | --- |
| 数据库异常泄漏节点租约，任务卡在运行中 | 调度和执行均保证释放租约；登记实际运行的任务，定时恢复没有工作线程持有的孤立任务；不中断正常任务 |
| 禁用账号仍能用旧会话运行或提交 | 接口与入队服务检查账号状态；禁用账号踢出已有登录会话 |
| 赛后公开代码后还能延长比赛 | 已结束的比赛禁止延长；公开代码的比赛禁止延长；管理端只向可延长比赛显示操作 |
| 固定 120 秒预算误算选手超时 | 按用例、轮数和语言限制计算预算；整体保护触发为判题服务异常，不计 ACM 罚时；每用例的真实超时判断保留 |
| Java 固定 96 MiB 堆忽略配置 | 按语言内存配置分配运行堆，保留 JVM 开销，仍执行节点实际内存限制；JDK 27 不变 |
| 排名逐个参与者查询并读取完整提交历史 | 数据库窗口聚合成绩与罚时，配合两次查询和最多 5 秒缓存；提交完成、重判和题单操作后失效 |
| 每次提交复制完整题目和参考解 | 不可变内容按 SHA256 共享，提交只存引用和自身代码；历史快照按小批次幂等转换，仍支持读取旧格式 |
| 登录、参数、限流拒绝没有操作日志 | 增加请求过滤与响应结果采集，覆盖控制器调用前的拒绝；正常操作仍由原日志切面记录，每次只记录一条；不记录请求源码或凭证 |
| 用户端运行位字段不一致 | 使用 `availableSlots`，保留 `freeSlots` 兼容字段；忙碌状态正常显示 |
| 旧请求覆盖新选中的运行记录 | 取消旧轮询并校验请求代次；提交响应、历史列表和页面卸载也受代次保护 |

另外，补齐默认 H2 模式所需的 JSON/数值兼容函数，MySQL 继续使用原生函数。判题节点的编译缓存过期时间调整为 10 分钟，执行期间访问会续期；引擎重启时清理失效缓存文件。两台节点均使用更新后的控制脚本。

练习仍不限累计提交次数：可选每日额度默认 `0`，不启用。普通题库与题单进度继续独立记录，每个账号已获得的绿色通过标记保留；题单成绩继续以有效判题结果重算。
