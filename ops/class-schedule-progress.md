# 班级课表异步采集

## 管理端操作

- 点击「立即采集」，在弹窗中选择单个学期或全部学期，再输入一次性教务账号密码。
- 提交后关闭配置弹窗，打开独立进度弹窗。请求只创建任务，不等待采集完成。
- 进度显示身份验证、学期发现、逐页采集、事务写入四个阶段；四种来源各自显示已解析页数、总页数、去重后条数和源站原始总数。数量动画只向服务端已返回的数据过渡，不虚构进度。
- 关闭进度弹窗不取消任务。刷新页面后可通过「查看采集进度」恢复。需要短信验证时仅发起管理员可续验，同一批次继续执行。
- 采集记录按批次分页，默认只显示每个学期/来源的最新结果。旧过程保留在单独展开、分页的历史记录中，旧 RUNNING 事件标为「过程记录」。

## 接口

- `POST /api/class-schedule/admin/pull`：`batchId`、`term`（空为全部学期）、`account`、`password`；立即返回 `accepted` 和 `batchId`。
- `GET /api/class-schedule/admin`：概览和 `activeBatchId`，用于恢复正在执行的任务。
- `GET /api/class-schedule/admin/pull/progress?batchId=...`：批次状态、最新事件、学期完成数、每来源的页数/条数。
- `POST /api/class-schedule/admin/pull/mfa`：提交短信验证码，后台验证并恢复该批次。
- `GET /api/class-schedule/admin/batches?page=1&size=10&status=SUCCESS&search=...`：最新结果列表，服务器分页和筛选。
- `GET /api/class-schedule/admin/pull/history?batchId=...&page=1&size=20`：不可变历史过程，按时间倒序分页。

## 一致性与限速

- 一个服务实例只允许一个活动采集任务；相同发起人、相同活动批次重复提交不重复执行。
- 一个工作线程顺序访问教务系统，继续保持原有请求间隔，不并发抓取。
- 每页 JSON 返回后立即解析、去重并持久化结构化进度，再请求下一页。总页数根据源站实际返回的分页大小计算，不能直接采用请求的 50000。源站没有总数时显示未知，直到明确空页确认结束。
- 页面读取中断、分页截断或任意来源失败，不发布半套课表。四类来源全部获取后，使用原有四表事务统一替换学期快照。
- 原始条数与去重后条数分开，允许源站少量重复数据。失败事件不抹掉此前已获取的页数和数量。
- 密码不入库，短信上下文只存内存。短信等待超时释放任务；服务重启后历史未终结批次明确记录为中断失败，避免永久显示采集中。
- 历史批次编号兼容旧版的 base36 时间戳/随机后缀，新建批次仍要求 UUID。旧日志没有整体状态记录时按最后事件读取；未终结的历史批次在重启恢复时补充一次整体失败记录，保留原始过程和数量。
- 浏览器每 2 秒串行查询一次进度，终态停止轮询；请求代次隔离避免旧响应覆盖新批次。尊重系统减少动态效果设置。

## 回归

- `ClassSchedulePagingTest`：每页先解析再上报、实际分页大小、去重计数、总数未知、截断保护。
- `ClassScheduleProgressTest`：最终状态去重、完整分页历史、失败计数保留、短信续验状态和重启恢复。
- `ClassScheduleTaskServiceTest` / `ClassScheduleControllerTest`：立即返回、单任务与幂等、短信归属、续验、超时释放和权限。
- `sap-admin/scripts/class-schedule-ui-check.cjs`：本地接口 fixture 完整验证两个范围、弹窗交接、逐页动画、刷新恢复、短信验证、终态和窄屏布局。不访问教务系统。
- `ops/class-schedule-live-check.cjs`：生产环境登录后仅 GET 检查，验证批次/历史分页与滚动位置的弹窗居中，不触发真实采集。
