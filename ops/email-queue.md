# 邮件事件与数据库队列

实现范围：五个独立代码事件、可配置模板绑定、受绑定保护的模板删除、管理端按钮、发送队列、发送日志、失败处理。

- 业务提交事件 + 收件用户 + 参数 + 幂等键，不引用模板 ID。入队保存渲染后的内容快照，之后改模板不影响队列。
- 数据库全局发送租约、持久化冷却时间；每次发送结束后冷却至少 65 秒。队列为空停工，入队在事务提交后唤醒；启动与每天北京时间 08:00 兜底唤醒。
- 发送与失败转存/日志/出队分开，数据库完成阶段原子提交。SMTP 不支持数据库事务，不能承诺 exactly-once；宕机后过期的发送中记录转为结果未知，不自动重发。
- 正文加密保存，日志不保存正文或验证码。失败详情按管理员权限展示；验证码过期不发、不允许原验证码人工重试，必须重新申请。
- 失败可批量重试/忽略/物理删除。重试与删除采用行锁，避免并发操作重复入队。
- 不更改历史业务数据，不补发历史注册/会员邮件。现有停用模板不会被自动启用。
- 本地测试使用 H2 与模拟 SMTP，不向真实用户发送测试邮件。

## 业务接入与上线行为

| 代码事件 | 默认模板标识 | 触发位置 |
| --- | --- | --- |
| ACCOUNT_REGISTERED | account.registered | 账号注册成功 |
| PASSWORD_CODE | account.password-code | `PasswordRecoveryService` → `EmailBusinessHooks.passwordCode`，找回密码邮件 |
| MEMBER_JOINED | member.upgraded | 后台升级会员、入会审批升级 |
| ISSUE_REPLIED | app.issue-replied | 管理员回复 App Issue（不通知管理员自己） |
| STUDY_REVIEW_REQUESTED | study.review-reminder | 学员提交作业后，提醒对应负责人评分；同一活动/周期/负责人每天最多一封 |

验证码业务仍由调用方生成并校验验证码、保存有效期；本次不改变现有密码认证流程。
收件地址使用用户资料的 QQ 邮箱；无有效 QQ 的事件记为跳过，不产生邮件。
注册介绍可在事件绑定处填写；其余业务变量不允许由模板管理页面伪造为固定参数。

首次启动创建队列表、失败表、日志表、绑定表、去重表和全局工作器状态表；按上述模板标识匹配兼容模板。手动解绑会持久保留，重启不覆盖。
全局暂停时允许继续入队；重新开启全局开关会唤醒队列。管理端的测试发送同样进入队列，不绕开 65 秒间隔。

## 本地回归

- 使用 Java 21 执行 `mvn clean test`（后端目录）。队列用 H2 MySQL 模式与模拟 SMTP 测试，不连接线上数据库。
- 管理端执行 `npm run build`；`scripts/email-ui-check.cjs` 通过本地 Vite 页面和拦截 API 验证绑定删除保护、解绑、失败详情与重试。
- SMTP 交付与数据库无法组成原子事务：数据库未能确认结果或租约过期时，记录转入“结果未知”，需要人工决定是否重试。
- 正式部署后首次启动创建线上队列表并完成默认模板绑定，不会自动启用停用模板。

## 绑定与日志显示规则修正

- 绑定要求主题与 HTML 正文中的占位参数集合和代码事件完全相等（忽略顺序、重复及占位符内的首尾空格）。不能只满足子集关系：仅含 `name` 的入会模板不能绑定 Issue 事件。
- 前端筛选、后端绑定、首次默认绑定、编辑已绑定模板和业务入队共用此要求。旧的不匹配绑定标记异常并跳过发送，不影响原业务提交，需要管理员重新绑定；不自动解绑或启用模板。
- 管理端发送日志使用 `/api/email/delivery/messages`，按 `message_id` 展示最后一条事件；无邮件编号的系统事件独立显示。顺序按递增日志 ID 判断，避免时间相同时状态错误。
- 展开行通过 `/api/email/delivery/logs/{id}/history` 分页查看该邮件的全部历史过程，历史 `SENDING` 显示“开始发送”。原 `/delivery/logs` 仍保留完整事件接口，用于审计和发送间隔验证。
- 增加 `(message_id,id)` 索引，避免查历史和查最新状态时逐条全表扫描。历史记录不会被覆盖或删除。

## 按代码事件创建模板

- 管理端 `/api/email/hooks` 返回代码定义的五个事件、必需参数、中文含义、预览示例和使用限制。参数集合直接来自 `MailHook.variables`，不从现有模板推断；新增参数须同时补齐代码中的参数说明。
- 新增模板先选用途，再插入占位符或生成基础主题/HTML。缺少、多出参数或验证码出现在主题时禁止保存；选定事件通过请求中的 `eventKey` 在后端再次校验。
- `eventKey` 只是本次编辑的目标契约，不创建绑定，也不替换已有绑定。保存后在代码事件区选择模板并保存绑定；已绑定模板在编辑器锁定用途，后端仍校验全部实际绑定。
- 保留独立手动模板用于测试发送。新建界面默认停用草稿，已有模板的启停状态不改变；参数示例不用于真实业务发送。
- 激活模板：模板列表 → 编辑 → 打开“启用模板” → 保存。自动生成邮件还要求正确绑定代码事件；执行发送要求全局 SMTP 发送开关开启。“唤醒队列”不会启用模板，历史跳过邮件不会补发，停用模板不撤回已入队邮件。
- 本地浏览器回归覆盖新建引导、4 个密码参数、插入/覆盖确认、示例预览、保存草稿、验证码主题限制和旧绑定/日志功能。编辑器内覆盖确认独立保留动态层级，避免被编辑弹窗遮挡。

## 邮件业务上下文日志

- `sys_mail_log.context_json` 保存业务触发时的快照：事件中文名称、触发原因、涉及用户账号/姓名/ID、业务触发人，以及明确选取的业务详情。启动时通过幂等列迁移补齐，不改现有模板参数或绑定。
- 注册记录注册账号姓名；会员升级记录会员和触发者；密码验证记录用途与有效期，不复制验证码；Issue 回复记录问题/回复编号、标题、内容摘要、状态和管理员；学习提醒记录活动、小队、周期、待评分人数与提交学员。
- 未绑定、停用、参数不匹配、无有效邮箱也记录上下文。队列发送、失败、重试、完成通过邮件编号继承业务快照；本步执行人与最初触发人分开记录，系统发送不会覆盖原触发者。
- 不复制任意模板参数或 HTML 邮件正文。问题/回复仅保存纯文本摘要，每项最多约 1000 字，显式标注的密码、验证码、授权码等字段脱敏；日志接口继续仅管理员可访问。
- 新日志以快照显示，不随之后修改用户资料变化。旧日志不回写：可确定的旧注册事件按原 `actor_id` 关联当前账号姓名，并明确标为当前资料；其他历史缺失详情不猜测、不伪造。
- 管理端列表显示事件、用户、触发原因和本步执行人，展开包含业务详情与完整处理历史；队列和失败列表也通过已有 `(message_id,id)` 索引读取对应上下文。
