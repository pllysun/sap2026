# 日志分层与反馈自动关闭（2026-09-11）

## 运行规则

- `sys_log` 保存最近 90 天的逐条请求。旧入口 `/api/log/list` 同样限制 90 天。
- `/api/log/explore` 支持 Web / App / 全部，明细、接口、用户三个维度，所有列表及下钻独立分页（每页最多 100 条）。管理端新增独立历史归档视图。
- Android 请求标记 `X-SAP-Client: app`；管理专用路径归 Web。旧记录按路径推断，历史共享接口无法准确还原客户端，不能宣称是设备识别。
- 新记录保存路由模板（而非将每个资源 ID 当成不同接口）、业务结果码及耗时；异常调用也记录。旧结果码缺失显示“未记录”，不当成成功。
- 不记录请求正文、查询参数、密码、验证码、令牌。

## 归档与保留

- 启动 3 分钟后、之后每小时执行。每批最多 1000 行，一轮最多 20 批，历史积压分轮处理。
- `sys_log_archive` 按小时、接口、方法、来源、用户 ID / 名称、IP、操作描述、结果码聚合。保留次数、耗时总和/最小/最大、首末调用时间。
- 数据库锁行 `sys_log_archive_lock` 跨实例互斥；归档写入、增量数量校验、删除这一批明细在同一事务内。失败完整回滚，重跑不会重复累计；迟到旧记录继续累加。
- 不保存每一次旧请求的时间；小时、首末时间及次数明确标注为聚合，不伪造成单次调用。
- **`log_stats` 永远不随归档删除**，按年份查询所有历史热力图。旧版已经漏记的数据无法凭空恢复；新计数使用数据库原子增量，避免并发读改写丢失次数。
- 删除释放数据库内部可复用空间，不等同于立即缩小磁盘文件。首次上线前备份数据库，关注归档速度、表大小、索引与锁等待；不对线上直接执行全表清空或文件压缩。

## 自动关闭反馈

- 每小时最多处理 200 条；仅 OPEN、未删除、确实有维护者回复、最后活动超过 7 天的 Issue。
- 最近回复、重新打开或状态变更都会延后关闭；从未回复的 Issue 不受影响。
- 自动任务和人工回复/关闭/重新打开/删除都锁同一 Issue 行。检查、系统说明、关闭在同一事务；重复执行不会重复发系统说明。
- 系统作者/关闭者 ID 为 0，前端显示“系统”。不冒充维护者，也不额外发送邮件。
- App 当前没有重新打开入口，说明文字引导新建反馈或联系维护者重新打开。
