# 教务模式切换、班级缓存同步与日历

## 本次实现

- 教务模式切换先关闭模式选择面板，必要时确认教务协议，再提交模式。
- 取消协议保留原模式；旧版本遗留的未授权教务模式仍降回 Web。
- 绑定账号请求、身份探测和用户信息请求回写前校验当前登录上下文，避免切号后的旧响应覆盖新账号权限/数据源。
- 班级模式在进入 App、返回前台、切入班级模式时触发应用级单任务后台校验。
- 日历位于课表左侧，提供日视图和月历；读取当前课表（含自建课程）及自定义作息，不改变课表页选择的周数。

## 班级同步协议

`POST /api/class-schedule/sync`：需要登录且有基础 App 能力，每批最多 100 个班级/学期选择。

请求 `selections` 包含 `key / term / college / grade / major / className / revision`；可选 `force` 用于跨批补取。

服务端使用数据库快照和现有四表索引查询生成内容指纹，纳入课程、教师、教室、周次、节次及开学日期。不用数据库行 ID、行顺序或采集时间判断变化。

- 全部一致：只返回版本，不返回课程正文。
- 任一变化：返回该批全部课程。客户端若分了多批，会补取其他批后统一合并。
- 网络失败、响应不完整或学期不可用：不提交任何更新，不清空缓存。
- 旧缓存首次升级会建立班级身份及版本信息，可能产生一次全量更新。
- 保留当前课表、自建课程、手动日期、个性化设置和冻结的自定义课表；不会复活刷新期间删除的缓存。
- 所有请求串行，课程 JSON 的本地编码放后台；操作与流量沿用管理端统一日志机制。
